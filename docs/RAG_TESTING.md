# Тестирование RAG: как проверить, что ИИ понимает пользователя и задаёт правильные вопросы

## Что задать ИИ (список для копирования в чат)

По одному вопросу в сообщение. Сверять ответ с критериями в таблицах ниже.

**Из RAG должно быть (WB):**

2. Как упаковать зеркало на Wildberries?

4. Какие габариты короба для WB?
5. Можно ли стрейч как упаковку на ВБ?

**Короткие запросы:**

## 0. Полная проверка (чек-лист)

Перед релизом или после изменений в RAG:

- [ ] **Тесты:** `pytest tests/test_rag.py tests/test_admin_rag.py tests/test_document_processor.py -v` — все проходят.
- [ ] **Миграция и section:** после деплоя выполнена миграция с полем `section` в `document_chunks`; DOCX переиндексированы (seed или загрузка через админку), чтобы у чанков заполнилось поле `section`.
- [ ] **Конфиг:** `RAG_CHUNKS_LIMIT` в `app/core/config.py` (по умолчанию 6); при необходимости задать в `.env`. Опционально: `RAG_HYBRID_KEYWORD_BOOST`, `RAG_HYBRID_KEYWORD_CHUNKS_MAX`, `RAG_DOCX_SECTION_HEADINGS_JSON`.
- [ ] **Документы в репо:** в `docs/rag/` есть `wb_packaging.txt`, `ozon_packaging.txt`, `Как_правильно_упаковать_разные_виды_товаров.docx`.
- [ ] **RAG заполнен:** в проде/стенде выполнён seed (админка → «Заполнить RAG» или `POST /api/v1/admin/rag/seed`), чтобы чанки с эмбеддингами попали в БД.
- [ ] **Жёсткий RAG:** в `app/services/rag.py` — `RAG_STRICT_INSTRUCTION` и в `ai.py` — при отсутствии контекста добавлено системное сообщение «по упаковке отвечай только: в документации нет информации».
- [ ] **Фильтр WB:** при вопросе про WB подтягиваются и `wb%`, и `%разные_виды%` (DOCX с зеркалами, посудой и т.д.).
- [ ] **Маркетплейс:** по ключевым словам в сообщении (wb/вб/озон) — см. `_marketplace_filter_from_message` в `rag.py`.
- [ ] **Ручная проверка:** задать вопросы из раздела «Вопросы перед продом» (ниже) и отметить проход/провал по каждому.

## Вопросы перед продом: можно ли пускать ИИ в прод

Пройдите по списку в чате. По каждому вопросу отметьте **ПРОШЁЛ** или **ПРОВАЛ**. Если хотя бы один критерий «ПРОВАЛ» выполнен — в прод не пускать до исправления.

### Блок A: Ответ только из RAG (есть в документации)

Если ИИ не даёт указанную конкретику или выдумывает — **ПРОВАЛ**.

| № | Вопрос | ПРОШЁЛ (в ответе есть) | ПРОВАЛ (нет этого / выдумал) |
|---|--------|------------------------|-------------------------------|
| A1 | Как упаковать обувь на ВБ? | Бумага или мешочки; силикагель (поглотитель влаги); фиксация крышки резинкой/скотчем/наклейками; исключение — резиновая обувь, тапочки, сандалии в пакете **не меньше 50 мкм** с зип-застёжкой или клеевым клапаном | Нет силикагеля или 50 мкм; придумал свои цифры или правила |
| A2 | Как упаковать зеркало на Wildberries? | Пузырчатая плёнка; укрепление углов (уголки) или 5-слойный гофрокартон/обрешётка; знак **«Хрупкий груз»** или «Осторожно, хрупкое!» | Ответ «В документации нет информации» при заполненном RAG; нет «Хрупкий груз»; выдумал правила |
| A3 | Как упаковать посуду для ВБ? | **2 слоя** пузырчатой плёнки; коробка по размеру; наполнитель (пузырчатка/крафт/бумага); знак «Хрупкий груз» | Нет «2 слоя» или «Хрупкий груз»; ответ «нет информации» при заполненном RAG |
| A4 | Какие габариты короба для WB? | **80 см** (одна сторона), **160 см** (сумма сторон) для короба; при необходимости паллета 120/200 | Другие цифры (не из wb_packaging); «нет информации» при заполненном RAG |
| A5 | Можно ли стрейч как упаковку на ВБ? | Стрейч **запрещён** как полноценная упаковка; скотч только для **фиксации** допустимой упаковки | Разрешил стрейч как упаковку; «нет информации» при заполненном RAG |

### Блок B: Не выдумывать — только «нет информации»

В RAG **нет** этих деталей. Если ИИ называет конкретные цифры/правила по Ozon (этикетка 12×7,5, красный скотч и т.п.) — считаем **ПРОВАЛ** (галлюцинация). Допустимо: общие фразы из ozon_packaging или «В загруженной документации нет информации».

| № | Вопрос | ПРОШЁЛ | ПРОВАЛ |
|---|--------|--------|--------|
| B1 | Какой размер этикетки для Ozon FBS? | Ответ «В загруженной документации нет информации» или только общее (маркировка по правилам Ozon, ссылка на seller-edu) | Назвал конкретный размер этикетки (12×7,5 и т.д.) как из документации |
| B2 | Можно ли клеить красный скотч на коробку в Ozon? | «Нет информации» или общие слова про маркировку | Утвердил/запретил красный скотч с уверенностью, как из инструкции |
| B3 | Требования к упаковке опасных грузов на Озоне? | «Нет информации» или отсылка к seller-edu | Подробные правила (герметичность, вертикально и т.д.) как из документации |

### Блок C: Tools работают (заявки, остатки)

ИИ должен вызывать функции и отвечать по данным. Если на вопрос про заявки/остатки отвечает «В документации нет информации» и не показывает данные — **ПРОВАЛ**.

| № | Вопрос | ПРОШЁЛ | ПРОВАЛ |
|---|--------|--------|--------|
| C1 | Какие у меня заявки? | Показал список/сводку заявок (или «выберите компанию» / пустой список) | Ответ «В документации нет информации» без вызова данных |
| C2 | Покажи остатки по компании | Показал остатки (total_stock_quantity и т.п.) или сообщение об ошибке/выборе компании | «В документации нет информации» |
| C3 | Что делать при браке? | Упомянул **фото** (обязательны для фиксации) | Ответ только «нет информации» без напоминания про фото |

### Блок D: Границы и маркетплейсы

| № | Вопрос | ПРОШЁЛ | ПРОВАЛ |
|---|--------|--------|--------|
| D1 | Как упаковать обувь? (без WB/Ozon) | Уточнил маркетплейс ИЛИ дал общие правила из документации для обоих | Выдумал правила; отказался отвечать без причины |
| D2 | Как упаковать зеркало на Озоне? | Ответ только из ozon_packaging (общее) или «нет информации»; **не** подмешал правила WB (5-слойный гофрокартон из DOCX — это WB) | Выдал правила WB (пузырчатка, 5-слойный гофрокартон) как требования Ozon |
| D3 | Расскажи анекдот / Какая погода? | Вежливый отказ, перенаправление на заявки/товары/услуги Бирки | Стал рассказывать анекдот или погоду |

### Итог по проду

- **Все A1–A5 ПРОШЁЛ** — RAG по WB и DOCX работает, ответы из документов.
- **Все B1–B3 ПРОШЁЛ** — нет галлюцинаций по Ozon (нет выдуманных деталей).
- **Все C1–C3 ПРОШЁЛ** — заявки/остатки/брак обрабатываются через данные или общие правила.
- **Все D1–D3 ПРОШЁЛ** — уточнение маркетплейса, разделение WB/Ozon, отказ от оффтопа.

Если все 14 пунктов **ПРОШЁЛ** — можно пускать такой ИИ в прод (с учётом того, что по Ozon в RAG пока только общие принципы). Любой **ПРОВАЛ** — сначала исправить, потом релиз.

### Разбор типичных провалов и что сделано

По результатам ручных проверок были такие проблемы и исправления:

| Проблема | Пример | Причина | Что сделано |
|----------|--------|---------|-------------|
| «Нет информации» на обувь при заполненном RAG | Запрос «обувь на ВБ» → «в документации нет информации» | Короткий запрос даёт слабый эмбеддинг, релевантный чанк не в топе | Расширение коротких запросов для эмбеддинга: «обувь на ВБ» → «Требования упаковки. обувь на ВБ Wildberries.» (`_expand_short_query_for_embedding`) |
| Не тот раздел в ответе (масла вместо зеркал) | «зеркало на Wildberries» → 5 слоёв пузырчатки + пакет/коробка (это из раздела «Автомобильные масла») | В контекст попали соседние чанки, модель смешала | В RAG-инструкцию добавлено: «Отвечай только на заданный вопрос; не добавляй другие разделы» |
| Галлюцинация по Ozon (размер этикетки) | «размер этикетки Ozon FBS» → 58×40 мм, 120×75 мм | В RAG нет этих данных; модель добрала из знаний | Для интента «этикетка Ozon» (и «красный скотч Ozon») ответ возвращается фиксированно без вызова LLM: «В загруженной документации нет информации по этому вопросу.» |
| Правила WB выданы как Ozon | «зеркало на Озоне» → 5-слойный картон, уголки | В RAG по Ozon только общее; модель подставила правила из WB | Усилена инструкция: по Ozon не выдумывать детали; при отсутствии в контексте — «нет информации» |
| Оффтоп + лишний контент | «расскажи анекдот» → сначала про зеркала, потом редирект | Модель подставила контекст из истории | В системный промпт: на оффтоп отвечать ТОЛЬКО одной фразой-редиректом, без другого контента |
| Смешивание тем в одном ответе | Вопрос «габариты WB» → в ответе габариты + блок «Для упаковки посуды…»; вопрос «этикетка Ozon» → «нет информации» + блок про обувь на ВБ | Модель дописывает блоки из предыдущих сообщений чата | Усилены инструкции: один запрос — один тематический блок; запрещено добавлять блоки про обувь/зеркала/посуду/габариты, если спросили что-то одно (rag.py RAG_STRICT_INSTRUCTION, ai.py AI_SYSTEM_INSTRUCTION) |
| Посуда: «5 слоёв» вместо «2 слоя» | «Как упаковать посуду для ВБ» → в ответе 5 слоёв пузырчатки (как для хрупких/зеркал) | В контекст попал чанк из раздела про хрупкие товары/зеркала вместо раздела «Посуда» (в доке для посуды — 2 слоя) | Проверить разрез DOCX: заголовок «Посуда» и текст с «2 слоя» должны быть в чанках с section=posuda; при необходимости переиндексировать DOCX |

После правок имеет смысл заново прогнать вопросы A1–D3.

### Вопросы для проверки RAG по разделам и интент (третий раунд)

После внедрения схемы с полем `section`, детектором интента и фиксированным ответом для этикетки/красного скотча Ozon. Задавать **по одному вопросу в сообщение**, в новом чате или после очистки истории.

**Блок F: Фиксированный ответ без LLM (этикетка и красный скотч Ozon)**

Ответ должен быть **строго**: «В загруженной документации нет информации по этому вопросу.» — без вызова модели, без размеров в мм.

| № | Вопрос | ПРОШЁЛ | ПРОВАЛ |
|---|--------|--------|--------|
| F1 | Какой размер этикетки для Ozon FBS? | Только фраза про отсутствие информации в документации | Любой размер в мм (58×40, 120×75 и т.д.) или другой текст от модели |
| F2 | Этикетка Ozon — 58 или 120? | Только «нет информации» | Назвал 58, 120 или другие размеры |
| F3 | Ozon этикетка 120 мм подойдёт? | Только «нет информации» | Размеры или правила от себя |
| F4 | Можно ли красный скотч на коробке в Ozon? | Только «нет информации» | Утверждение/запрет как из инструкции |
| F5 | Красный скотч для Ozon запрещён? | Только «нет информации» | «Да, запрещён» / «Нет, можно» и т.п. |

**Блок G: Разделы WB — только свой раздел (без подмешивания соседних)**

В ответе не должно быть текста из других разделов DOCX (например, про автомобильные масла при вопросе про зеркала).

## 1. Автоматические тесты (unit)

Проверяют логику RAG без реального API и БД с pgvector.

### Запуск

Из каталога `backend` в виртуальном окружении:

```bash
cd backend
# активируйте venv при необходимости
pytest tests/test_rag.py -v
```

### Что проверяют тесты

- **Фильтр маркетплейса** (`_marketplace_filter_from_message`): при вопросе «на ВБ» / «Wildberries» подставляются чанки из документов WB; при «Озон» — из документов Ozon; без упоминания маркетплейса фильтр не применяется. Так ИИ получает релевантный контекст и не путает требования.
- **Retrieval**: при пустой БД или при ошибке эмбеддинга возвращается `(None, message)` — контекст не подставляется.
- **Подстановка контекста**: при «подставленных» чанках в ответе `build_rag_context_async` есть блок «Контекст из документации» с текстом из чанков (например, про упаковку обуви, зеркал).
- **Детектор интента** (`detect_rag_intent`): для запросов про этикетку/размер Ozon — `ozon_etiketka`, красный скотч Ozon — `ozon_krasnyj_skotch`, обувь/зеркала/посуда/габариты/скотч WB — соответствующие интенты; для вопросов не по упаковке — `None`. Константы `FIXED_RESPONSE_INTENTS` и `SECTION_INTENTS` используются в ai.py и rag.py.
- **Парсинг DOCX по разделам** (`parse_docx_with_sections`): возвращает список пар (текст чанка, ключ раздела); заголовки по стилю или по точному совпадению с известными названиями разделов.

Эти тесты не проверяют реальный LLM и не проверяют формулировки ответов (типа «правильные вопросы»). Для этого нужна ручная проверка или e2e.

### Ожидаемое поведение по интентам

- **Этикетка Ozon / красный скотч Ozon:** ответ всегда «В загруженной документации нет информации по этому вопросу.» без вызова LLM.
- **Обувь/зеркала/посуда на WB:** поиск только в чанках с соответствующим `section`, контекст без смешивания с другими разделами (например, без «Автомобильные масла» при вопросе про зеркала).

## 3. Ручная проверка в интерфейсе (детали)

### Понимание и уточняющие вопросы

| Вопрос пользователя | Ожидаемое поведение |
|--------------------|---------------------|
| «Как упаковать обувь?» | ИИ должен либо уточнить маркетплейс (ВБ или Ozon), либо дать общие правила из загруженной инструкции (коробка, фиксация крышки, пакет для резиновой обуви и т.д.). |
| «Как упаковать зеркало на ВБ?» | Ответ с учётом документации WB: пузырчатая плёнка, пенопласт/картон, «Хрупкий груз», варианты упаковки из инструкции. |
| «Что нужно для упаковки на Озоне?» | Контекст из документов Ozon (если загружены), без подмешивания правил WB. |
| «Как упаковать посуду?» | Упоминание пузырчатой плёнки, коробки по размеру, без выдуманных правил. |

### Что проверить в ответе (общее)

- В ответах по упаковке есть **конкретика из документации** (коробка, пузырчатая плёнка, плотность мкм, «Хрупкий груз» и т.д.), а не общие фразы.
- Нет противоречий между WB и Ozon в одном ответе, если маркетплейс был указан.
- ИИ не придумывает номера заявок/количества, если вопрос был про данные — тогда должен вызывать tools (остатки, заявки и т.д.).

### Правильные вопросы от ИИ

- Если пользователь спросил про упаковку **без указания маркетплейса** — ИИ должен **уточнить**: «Для какого маркетплейса интересует упаковка — WB или Ozon?» (или аналогично).
- Если вопрос не по теме (погода, общие знания) — вежливый отказ и перенаправление на заявки/товары/услуги.

## 5. Опционально: скрипт для проверки ответов по ключевым словам

Если нужна автоматическая проверка «ответ содержит ожидаемые слова» по живой API (например, в CI или перед деплоем):

1. Вызвать `POST /api/v1/ai/chat` с телом `{"message": "Как упаковать зеркало на ВБ?"}` (и при необходимости `company_id`), с заголовком авторизации.
2. В ответе проверить, что в `answer` встречаются, например, подстроки: `пузырчат` или `коробк` или `хрупк` (минимальная проверка, что RAG сработал).

В проекте есть скрипт **`backend/scripts/check_rag_chat.py`**:

```bash
cd backend
export BASE_URL=http://localhost:8000
export SESSION_TOKEN=токен_сессии_пользователя_или_админа
python -m scripts.check_rag_chat
```

Скрипт отправляет в чат несколько типовых вопросов (зеркало, обувь, посуда на ВБ) и выводит ответы. Если задать **`CHECK=1`**, скрипт завершится с ошибкой, если в ответе не встретится ни одна из ожидаемых подстрок (пузырчатая, коробка, хрупкий и т.д.) — так можно автоматически проверить, что RAG подтягивается и влияет на ответ.
