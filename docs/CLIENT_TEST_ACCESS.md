# Ограниченный доступ для теста клиента в production

Перед выдачей клиенту доступа в прод убедитесь, что у него минимальные права и изоляция данных.

---

## Роли и изоляция

- **client** — видит только свои компании, заявки, товары. Не имеет доступа к админке, адресам, настройкам AI, другим компаниям.
- **admin** — полный доступ. В production в `ADMIN_TELEGRAM_IDS` должны быть только ваши/внутренние Telegram ID, **не** ID тестирующего клиента.

Пользователь создаётся при первом входе через Telegram Mini App; роль определяется так: если `telegram_id` входит в `ADMIN_TELEGRAM_IDS` — роль `admin`, иначе — `client`.

---

## Подготовка ограниченного доступа

1. **Не добавляйте Telegram ID клиента в `ADMIN_TELEGRAM_IDS`** в `.env` на проде. Тогда при входе через бота клиент получит роль `client` и не увидит админку и чужие данные.

2. **Тестовая компания:**
   - Клиент может создать компанию сам через приложение (Клиент → Компании → добавить по ИНН). Для теста предпочтительно использовать тестовый ИНН или отдельную компанию.
   - Либо вы создаёте компанию заранее и привязываете её к пользователю клиента (через БД/скрипт), если у вас есть его `user_id` после первого входа.

3. **Проверка роли пользователя (опционально):**
   ```bash
   docker compose -f docker-compose.prod.yml exec backend python -m scripts.fix_admin_and_companies list
   ```
   Убедитесь, что у тестового клиента в списке роль `client`, а не `admin`.

4. **При необходимости принудительно снять admin:**  
   Временно уберите Telegram ID клиента из `ADMIN_TELEGRAM_IDS`. Затем выставить роль `client` одному пользователю:
   ```bash
   docker compose -f docker-compose.prod.yml exec backend python -m scripts.fix_admin_and_companies client --telegram-id=123456
   ```
   (подставьте реальный Telegram ID клиента). Либо выполните `fix` — скрипт выставит `admin` только тем, кто в `ADMIN_TELEGRAM_IDS`; остальные не меняются. Чтобы у пользователя гарантированно была роль `client`, его не должно быть в `ADMIN_TELEGRAM_IDS`.

---

## Минимальные права для теста

- Клиент заходит через Telegram → получает роль `client`.
- Создаёт или выбирает одну тестовую компанию.
- Видит только свои заявки, товары, отгрузки; не видит других компаний и админ-разделы.
- API-ключи WB/Ozon (если тестируете интеграции) лучше завести тестовые в личном кабинете маркетплейса и указать их в настройках компании в приложении.

Автоматические тесты изоляции и авторизации: [backend/tests/test_auth.py](../backend/tests/test_auth.py), [backend/tests/test_security.py](../backend/tests/test_security.py), [backend/tests/test_companies.py](../backend/tests/test_companies.py). Перед выдачей доступа убедитесь, что они проходят в CI или локально.
